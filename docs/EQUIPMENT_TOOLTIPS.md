# Tooltip presentation

All shared tooltip backgrounds use an opaque dark surface with a black outline and small stepped ornaments. Equipment uses its custom rarity for the frame and title: Normal white, Magic blue, Rare yellow, Unique orange. Other tooltips use the neutral frame.

Equipment cards keep the existing stat calculations. The header shows the item icon, rarity, equipment type, requirements and quality. Core values align to the right. Prefixes and suffixes have separate headings and occupied/maximum counts; a hybrid rune consumes one affix slot while showing each of its components. Enchantments retain copy counts, empty slots and Shift descriptions. Durability appears for damageable equipment, including without advanced tooltips.

Holding the configurable Show Details key (Shift by default) shows one tier label per rune and that tier's possible numeric range for **each component** of the rune, using the same `StatComponent` range data used by crafting. Examples: `[T8] [7-11]`, `[T8] [27-34%]`. Boolean effects show a tier label without a numeric range. Unique effects retain the `TX` convention. Natural/artificial colors, cryptic-stat obfuscation, modified base-value colors and unmet-requirement warnings are preserved.

Cards wrap their text to the available width and stay inside the screen margins. Oversized cards show an `Alt + wheel to scroll` hint and clip only complete text lines. The scroll target expires when the tooltip disappears; ordinary wheel input remains available to the screen until the pointer enters the anchored card, where it scrolls the card. Hybrid rune components share an indented bracket, with a gap separating distinct runes. While Show Details is held, linked names, runes, enchantments and statistics open the contextual Compendium layer without closing the underlying container. See `CONTEXTUAL_GUIDE.md`.

The presentation uses invisible text-style insertion markers, preserving complete readable `Text` values for other consumers. Tagged lines become tooltip components, and a scoped DrawContext wrapper groups them into a card. The original item stack supplies its icon when available. Foreign tooltip components remain in the render sequence. Rarity context is restored after every render, including nested tooltips and errors, so a normal tooltip cannot inherit a previously hovered item's rarity.

Validation includes the Gradle regression/build checks and a native test in an isolated copy of the supplied modpack: four rarities, regular item tooltips, all six rare affixes, hybrid component ranges, percentages, boolean effects, requirement warnings, screen-edge placement, multiple GUI scales and scrolling. Native fixtures and captures are retained under `build/equipment-tooltip-*` and `build/mount-modpack-smoke/equipment-tooltip-gallery`; they are not shipped.
